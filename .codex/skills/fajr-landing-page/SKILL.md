# Fajr Now Landing Page Workflow

Use this skill for any substantive Fajr Now homepage, landing-page, positioning, website-copy, or marketing-design task.

## Authority order
1. Explicit user instruction
2. `AGENTS.md` product doctrine
3. `.agents/product-marketing.md` shared marketing context
4. Evidence from customer research
5. Specialist skill guidance
6. Generic marketing conventions

If these conflict, the higher item wins. Truth, religious sensitivity, user dignity, reliability, privacy, and clarity always outrank conversion tricks.

## Required sequence

### 1. Establish product truth — `product-marketing`
Read `AGENTS.md` and `.agents/product-marketing.md`. If context is missing or stale, update it first. Distinguish confirmed facts, hypotheses, unknowns, and unsupported claims.

### 2. Ground language — `customer-research`
Use available first-party evidence and, when explicitly researching, credible public sources. Extract JTBD, pains, triggers, alternatives, objections, and real vocabulary. Never invent research. Feed validated findings into product context.

### 3. Draft messaging — `copywriting`
Define the page's single primary job and action. Draft a coherent argument from hero through final action. Prefer clarity, specificity, and customer relevance over cleverness.

### 4. Tighten — `copy-editing`
Run the seven sweeps plus the anti-AI pass. Remove unsupported claims, generic startup language, filler, repetition, melodrama, and copy that could belong to any alarm/wellness/productivity app.

### 5. Audit conversion — `cro`
Test whether a cold visitor can quickly understand what Fajr Now is, why it matters, why it is different, what can be trusted, and what to do next. Identify friction and objections. Treat optimizations as hypotheses unless measured.

### 6. Behavioral advisory — `marketing-psychology`
Apply only mental models that increase comprehension, reduce activation energy, or help users make informed decisions. Explicitly reject shame, religious guilt, fake scarcity, false urgency, dark patterns, coercion, addiction loops, or fabricated social proof.

### 7. Implement presentation — `frontend-design`
Only after messaging is stable, shape typography, hierarchy, spacing, imagery, motion, responsive behavior, and interactions around the message. The design must feel native to Fajr and the dawn/morning subject rather than like a generic startup template.

### 8. Final integrated QA
Re-read the result as four reviewers:
- A first-time Muslim visitor: Do I immediately understand it and feel respected?
- A skeptical buyer/user: Are claims credible and limitations honest?
- A UX/copy editor: Is every word and section doing one useful job?
- A Fajr Now product steward: Does this strengthen ownership of the Muslim morning rather than drift toward a generic alarm or Islamic superapp?

Do not ship until major conflicts are resolved.

## Fajr-specific messaging boundaries
- Lead with the Muslim morning/Fajr problem, not feature inventory.
- Reliability is important but never guarantee waking or imply impossible OS certainty.
- Encourage without shaming inconsistent users.
- Do not posture as a religious authority.
- Avoid preachy, sentimental, cute, hype-heavy, or generic productivity language.
- No invented testimonials, user counts, success rates, endorsements, or religious claims.
- Prefer calm confidence and useful specificity.

## Output for website work
When source files are available, make the copy and design changes in the implementation and validate responsive behavior. When website source files are not available, produce a clearly labeled implementation-ready copy/design brief rather than pretending code was changed.
